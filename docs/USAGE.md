# Установка GitPosted

## Сервер и адрес

Установщик предназначен для нового отдельного сервера Ubuntu Server 24.04 LTS.
Перед запуском понадобятся SSH-доступ с root/sudo, не менее 4 ГиБ свободного
места, публичный IPv4, доступ к пакетным репозиториям и исходящему HTTPS.
Входящие порты 80 и 443 нужны для сайта и выпуска сертификата. Порт SSH оставьте
доступным для себя.

Сервер с существующими сайтами, MySQL, занятыми путями или конфликтующими службами
не считается чистым. Предварительная проверка останавливает такую установку;
обходить её удалением чужих сайтов и баз не следует.

Адрес по умолчанию — публичный IPv4 сервера. Для своего домена заранее настройте
A-запись на этот IPv4. Если есть AAAA или несколько A-записей, все адреса должны
соответствовать проверке целевого сервера; неподходящую AAAA уберите в DNS до
запуска. Сам установщик DNS не меняет.

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash
```

С доменом:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash -s -- --host example.org
```

С явным IPv4, если автоматическое определение неоднозначно:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash -s -- --public-ip YOUR_PUBLIC_IPV4 --host example.org
```

Если вы уже вошли как root, вместо `sudo bash` можно использовать `bash`.
`curl` и `python3` должны быть доступны до запуска; Python 3 обычно входит в
Ubuntu Server. Основные зависимости приложения ставит сам bootstrap.

Для предварительной проверки без установки добавьте `--dry-run` к параметрам.
Загрузчик всё равно скачает и проверит release во временном каталоге, а bootstrap
выполнит проверку совместимости сервера без установки служб.

## Личная ссылка и мастер

После установки зависимостей и доверенного HTTPS в SSH появится личная ссылка
вида `https://<адрес>/install/#setup=<одноразовое-значение>`.
Откройте её в браузере целиком. Браузер автоматически выполнит вход и уберёт
fragment из адресной строки. Вручную переносить значение в отдельное поле не
нужно. Не отправляйте ссылку другим людям и не публикуйте SSH-вывод с ней.

Далее мастер предложит:

1. Проверить адрес сервера; при необходимости подключить домен до настройки ботов.
2. Задать логин администратора и пароль с подтверждением. Пароль — от 12 символов,
   не более 72 байт UTF-8; хранится хеш, а не открытый пароль.
3. Независимо включить Telegram и/или МАКС и проверить введённые bot tokens.
4. При необходимости заполнить часовой пояс, контакт поддержки, hCaptcha и
   Telegram API ID/hash.
5. Проверить итоговые параметры и запустить установку приложения.

Проверка токена читает личность бота и состояние его webhook. Она не отправляет
сообщений. Если бот обслуживает другое приложение, перенос webhook требует
явного подтверждения в мастере. После переноса новые события этого бота поступают
в данный GitPosted. Для первого знакомства удобно использовать отдельного бота.

Во время создания схемы и регистрации webhooks обе очереди остаются выключенными.
Мастер включает только выбранные платформы после проверки. Пропущенная платформа
не требует токена и не участвует в API-регистрации.

## Дополнительные функции

**hCaptcha.** Можно оставить выключенной. Административный вход при этом сохраняет
пароль, CSRF-защиту и ограничение числа попыток. Если вы включили hCaptcha,
укажите реальные sitekey/secret для своего адреса; неверная конфигурация не
превращается в обход проверки.

**Telegram API ID/hash.** Эти параметры нужны дополнительному bot MTProto worker
для чтения постов по ссылкам и настоящих репостов. Их можно не указывать при
обычной установке. Ввод параметров в мастере сам по себе не создаёт и не
авторизует bot session. Её подключают отдельно с разрешения владельца сервиса.
Личный Telegram-аккаунт, телефон, SMS-код и пароль 2FA для этой серверной bot
session не используются.

**Контакт поддержки.** Необязателен. Если он не заполнен, приложение не подставляет
контакт разработчика или чужого бота вместо владельца вашей установки.

**Платформы позже.** Telegram и МАКС можно подключить через `/control/` после
первоначальной установки. Для публикаций добавьте соответствующего бота в свой
канал с нужными правами и подключите канал в интерфейсе бота. Сама установка
готовых или тестовых постов не создаёт.

Если подключаемый бот уже обслуживает другое приложение, админка также попросит
отметить перенос webhook. До этого подтверждения внешний webhook не меняется.

## Продолжение после ошибки

Не запускайте новую установку поверх частично созданной базы. Повторно откройте
мастер в той же браузерной сессии и используйте продолжение сохранённого задания.
Завершённые шаги повторно не запускаются.

При ошибочном или отозванном токене до включения ботов мастер предложит изменить
параметры. Пароль и токены вводятся заново; уже созданная база сохраняется.
После начала включения доступно только продолжение существующего задания.
Если ошибка произошла при подключении домена, его можно исправить либо
продолжить настройку по IP.

Если нужна новая личная ссылка или подготовка HTTPS прервалась до открытия мастера:

```bash
sudo bash /opt/gitposted-installer/bootstrap.sh --resume
```

Если первая подготовка не успела разместить этот каталог, повторите исходную
команду загрузки с теми же параметрами и `--resume`. Не сбрасывайте state-файлы и
не удаляйте базу для устранения ошибки. Сообщение о занятом задании означает, что
нужно дождаться его завершения.

Полный пакет сохраняется в `/opt/gitposted-installer` до установки зависимостей.
Поэтому продолжение после ошибки apt не требует уже установленного PHP и
работает после очистки временного каталога загрузчика.

После успешного завершения мастер закрыт для новых настроек. Вход администратора
доступен по `https://<адрес>/control/` с созданными вами логином и паролем.

## Где находится установленное приложение

| Назначение | Путь |
| --- | --- |
| Пакет bootstrap и временный broker | `/opt/gitposted-installer` |
| Активный release приложения | `/opt/gitposted/current/src` |
| Releases | `/opt/gitposted/releases` |
| Private config | `/etc/gitposted/config.php` |
| Медиа, runtime и storage | `/var/lib/gitposted` |
| Состояние первоначальной установки | `/var/lib/gitposted-installer` |
| Логи приложения | `/var/log/gitposted` |
| Учётная запись приложения | `gitposted` |
| База и локальный пользователь MySQL | `GitPosted`, `gitposted_app` |

Приложение обслуживается nginx и PHP 8.3 FPM. Apache и Docker не требуются.
Планировщик запускается cron каждую минуту от пользователя приложения. После
успешной установки временный root broker выключается. Сертификаты продлевает
отдельный systemd timer.

Config, данные БД, `.session`, импортированные `.blob`/`.json` и логи относятся
к private состоянию вашей установки. Не добавляйте их в публичный GitHub и не
публикуйте полные ответы диагностических команд с токенами или текстами постов.

## Сборка из исходников

Разработка и сборка не требуют подключать реальных ботов. В корне репозитория:

```bash
python3 -B tests/package_test.py
python3 -B tests/broker_test.py
php tests/application-test.php
php tests/wizard-test.php
node tests/ui.test.cjs
python3 -B scripts/build.py --output ../INSTALLER-RELEASE
```

Для запуска bootstrap непосредственно из исходников весь пакет и его родительские
каталоги должны принадлежать root и быть закрыты от записи других пользователей.
Обычный пользовательский clone под `sudo` предварительную проверку не пройдёт.
Для установки используйте публичную команду загрузки выше либо отдельный clone,
созданный root в каталоге root, например `/root/GitPosted`. Не меняйте рекурсивно
владельца пользовательского домашнего каталога ради обхода этой проверки.

PHP-проверки требуют PHP 8.3 и расширений приложения; Node.js нужен только для
UI unit tests. Сборщик создаёт `gitposted-installer.tar.gz` и его `.sha256` вне
дерева исходников. Внутри архива — `gitposted-installer/` и `MANIFEST.sha256`.
Секреты, SQLite-сессии, cache/pyc, symlink и лишние файлы сборщик отвергает.

Проверка распакованного release:

```bash
python3 -B scripts/build.py --verify-manifest /absolute/path/to/gitposted-installer
```

Она проверяет и SHA-256, и точный набор файлов. Публичный `install.sh` создаётся
из `scripts/release-loader.sh` с URL конкретного release и его реальной SHA-256
после сборки. Он не входит в собственный архив: это исключает циклическую
зависимость archive hash от загрузчика. Публиковать неподставленные placeholders
или выдуманный hash нельзя.
