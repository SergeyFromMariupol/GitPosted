# Установка GitPosted

## Сервер и адрес

Установщик предназначен для Ubuntu Server 24.04 LTS: нового чистого сервера
либо проверенной завершённой установки GitRePosted из совместимого установщика.
Перед запуском понадобятся SSH-доступ с root/sudo, не менее 4 ГиБ свободного
места, публичный IPv4, доступ к пакетным репозиториям и исходящему HTTPS.
Входящие порты 80 и 443 нужны для сайта и выпуска сертификата. Порт SSH оставьте
доступным для себя.

Существующие сторонние сайты, произвольный MySQL, занятые пути или конфликтующие
службы не разрешают автоматическую установку. Предварительная проверка
останавливает такой запуск; обходить её удалением чужих сайтов и баз не следует.
Исключение — завершённый соседний GitRePosted с проверенным состоянием, путями
и конфигурацией общего стека; порядок описан в следующем разделе.

Первая новая установка по умолчанию использует публичный IPv4 сервера; вторая
наследует текущий проверенный адрес первого проекта. Для своего домена заранее настройте
A-запись на этот IPv4. Если есть AAAA или несколько A-записей, все адреса должны
соответствовать проверке целевого сервера; неподходящую AAAA уберите в DNS до
запуска. Сам установщик DNS не меняет.

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash
```

С доменом:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash -s -- --host example.org
```

С явным IPv4, если автоматическое определение неоднозначно:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash -s -- --public-ip YOUR_PUBLIC_IPV4 --host example.org
```

Если вы уже вошли как root, вместо `sudo bash` можно использовать `bash`.
`curl` и `python3` должны быть доступны до запуска; Python 3 обычно входит в
Ubuntu Server. Основные зависимости приложения ставит сам bootstrap.

Для предварительной проверки без установки добавьте `--dry-run` к параметрам.
Загрузчик всё равно скачает и проверит release во временном каталоге, а bootstrap
выполнит проверку совместимости сервера без изменения конфигурации и установки
служб. Такая проверка не занимает адрес и не запускает публикации.
Это проверка путей, состояния и адреса, а не полный план APT/dpkg или гарантия
последующей установки всех зависимостей.

## Два проекта на одном сервере

Начиная с **0.1.0-rc.8**, новые установки обоих проектов используют постоянные
пути `/GitPosted/` и `/GitRePosted/`. Можно начать с любого проекта: полностью
завершите его браузерный мастер, затем установите второй.

| Размещение | GitPosted | GitRePosted |
|---|---|---|
| Общий IP без домена | `https://IP/GitPosted/control/` | `https://IP/GitRePosted/control/` |
| Общий домен | `https://example.org/GitPosted/control/` | `https://example.org/GitRePosted/control/` |
| Разные домены | `https://posted.example.org/GitPosted/control/` | `https://reposted.example.org/GitRePosted/control/` |

`IP` и домены в таблице замените своими. Без `--host` первая установка выбирает
публичный IP. Вторая без `--host` использует текущий проверенный адрес первого
проекта. Для разных доменов передайте каждому свой `--host`; для общего домена
укажите одинаковое имя либо не передавайте его второй установке. Все выбранные
имена должны иметь A-запись на IPv4 сервера. Установщик не меняет DNS.

Команды для общего IP или наследования адреса:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash
```

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash
```

Для домена добавьте к нужной команде `-s -- --host example.org` после `sudo bash`.
Для разных доменов укажите разные имена. Для предварительной проверки добавьте
`--dry-run`: она проверяет совместимость, но не заменяет установку зависимостей.

Главная `/` показывает ссылки на размещённые на этом адресе приложения.
У каждого проекта свой мастер (`/GitPosted/install/` или `/GitRePosted/install/`),
логин, пароль и админка. Персональная ссылка одного проекта не открывает другой.
Токены ботов должны быть разными; в каналы можно добавить обоих ботов с нужными
правами. Telegram и МАКС можно пропустить и подключить позже.

nginx, MySQL и PHP общие; базы `GitPosted`/`GitRePosted`, системные пользователи,
данные, конфигурации, cookies и службы приложений разделены. Один HTTPS-сертификат
общего адреса обслуживается установщиком, который первым занял этот адрес;
второй использует его. Продление выполняется автоматически. Приложения слушают
только внутренние порты, снаружи доступны через общий nginx.

Установщик проверяет соседний проект и использует общую блокировку. При
`SHARED_INSTALL_BUSY` дождитесь другого системного шага. При прерывании
продолжайте именно свой проект через `--resume`, а браузерное задание — в его
мастере. Не удаляйте state-файлы, блокировки и базы для обхода проверки.
Сторонние сайты или произвольная существующая MySQL этим режимом не подхватываются.

**Старые установки rc.7 и ниже:** корневые адреса `/control/` сохраняются.
Повторный загрузчик не обновляет и не переносит готовое приложение. Рядом с
проверенной старой установкой второй проект требует отдельный явный домен и
тоже использует прежний корневой режим. Общий адрес с постоянными путями
предназначен для двух новых установок rc.8 и новее; автоматической миграции
готовых установок в этом выпуске нет.

## Личная ссылка и мастер

После установки зависимостей и доверенного HTTPS в SSH появится личная ссылка
вида `https://<адрес>/GitPosted/install/#setup=<одноразовое-значение>`.
Откройте её в браузере целиком. Браузер автоматически выполнит вход и уберёт
fragment из адресной строки. Вручную переносить значение в отдельное поле не
нужно. Не отправляйте ссылку другим людям и не публикуйте SSH-вывод с ней.

Далее мастер предложит:

1. Проверить адрес сервера; при необходимости подключить домен до настройки ботов.
2. Задать логин администратора и пароль с подтверждением. Пароль — от 12 символов,
   не более 72 байт UTF-8; хранится хеш, а не открытый пароль.
3. Независимо включить Telegram и/или МАКС и проверить введённые bot tokens.
4. При необходимости заполнить часовой пояс, контакт поддержки, hCaptcha и
   Telegram API ID/hash.
5. Проверить итоговые параметры и запустить установку приложения.

Проверка токена читает личность бота и состояние его webhook. Она не отправляет
сообщений. Если бот обслуживает другое приложение, перенос webhook требует
явного подтверждения в мастере. После переноса новые события этого бота поступают
в данный GitPosted. Для первого знакомства удобно использовать отдельного бота.

Во время создания схемы и регистрации webhooks обе очереди остаются выключенными.
Мастер включает только выбранные платформы после проверки. Пропущенная платформа
не требует токена и не участвует в API-регистрации.

## Дополнительные функции

**hCaptcha.** Можно оставить выключенной. Административный вход при этом сохраняет
пароль, CSRF-защиту и ограничение числа попыток. Если вы включили hCaptcha,
укажите реальные sitekey/secret для своего адреса; неверная конфигурация не
превращается в обход проверки.

**Telegram API ID/hash.** Эти параметры нужны дополнительному bot MTProto worker
для чтения постов по ссылкам и настоящих репостов. Их можно не указывать при
обычной установке. Ввод параметров в мастере сам по себе не создаёт и не
авторизует bot session. Её подключают отдельно с разрешения владельца сервиса.
Личный Telegram-аккаунт, телефон, SMS-код и пароль 2FA для этой серверной bot
session не используются.

**Контакт поддержки.** Необязателен. Если он не заполнен, приложение не подставляет
контакт разработчика или чужого бота вместо владельца вашей установки.
Канал новостей задаётся отдельно в **админке → Telegram → Username канала новостей**.
Если поле пустое, строка новостей в приветствии скрыта.

**Платформы позже.** Telegram и МАКС можно подключить через `/GitPosted/control/` после
первоначальной установки. Для публикаций добавьте соответствующего бота в свой
канал с нужными правами и подключите канал в интерфейсе бота. Сама установка
готовых или тестовых постов не создаёт.

При подключении регистрируется меню команд выбранного бота. Если платформа
временно не подтвердила меню, мастер позволяет продолжить ту же установку.

Если подключаемый бот уже обслуживает другое приложение, админка также попросит
отметить перенос webhook. До этого подтверждения внешний webhook не меняется.

## Подключение Telegram-канала

В боте откройте **Настройки → Добавить канал**. Добавьте своего бота
администратором канала с правами отправки, редактирования и удаления сообщений.
Аккаунт, который подключает канал впервые, также должен быть его владельцем
или администратором в Telegram.

Отправьте один из вариантов:

- `@channel_username`;
- `t.me/channel_username` или `https://t.me/channel_username`;
- числовой ID канала со знаком минус;
- пересланное сообщение из этого канала.

Для закрытого канала используйте ID или пересылку. Пригласительные ссылки
`t.me/+...` и `t.me/joinchat/...` не подходят. Ссылка на отдельную публикацию,
личный аккаунт или группу не подключает канал. Дополнительные действующие
публичные имена канала принимаются наряду с основным именем.

После проверки бот сохранит канал и отправит личное подтверждение с эффектом
🎉. Отображение анимации зависит от клиента Telegram и его настроек.
Тестовый пост в канал при подключении не отправляется. GitPosted бесплатный:
в стандартном режиме подписка на подключённые каналы не требуется. Владелец
установки может изменить условия сервиса в панели управления.

## Оплата и доступ к Telegram-боту

Откройте **админка → Telegram → Доступ**. Доступны две независимые настройки:

- **Режим работы:** «Бесплатно» или «Подписка за каждый канал».
- **Кто может пользоваться:** «Все пользователи», «Только из списка» или
  «По каналам доверенных аккаунтов».

Категории **Telegram**, **МАКС**, **Подписки и тарифы** и **Общие** составляют
одну форму. Между разделами бокового меню можно переключаться без потери введённых данных.
Кнопка **Сохранить изменения** применяет настройки всех категорий. Ошибка
в одном поле не приводит к частичному сохранению остальных настроек.
Панель отмечает несохранённые правки; секретные поля после сохранения пусты.

По умолчанию выбраны бесплатный и открытый режимы. Для закрытого режима введите
положительные числовые ID аккаунтов, по одному на строку. Username в этом списке
не используется. Пустой список при выбранном закрытом режиме закрывает доступ
всем пользователям бота; веб-админка остаётся доступной.

В режиме **«По каналам доверенных аккаунтов»** этот список содержит ID владельцев,
от которых начинается доступ. Редакторы, модераторы и рекламные менеджеры их
каналов допускаются автоматически, с прежними правами только на назначенные
каналы. Собственные каналы они по умолчанию подключать не могут.

Чтобы разрешить сотруднику подключать свои каналы, откройте **Данные → Telegram →
Собственные каналы сотрудников**, найдите его по Telegram ID, включите
**Разрешить подключать собственные каналы** и нажмите **Сохранить доступ**.
Сотрудники подключённых им каналов получают доступ по той же цепочке.
Сам по себе этот переключатель не допускает постороннего пользователя в бота:
он должен оставаться связан с одним из доверенных владельцев.

После отзыва связывающих прав доступ по этой цепочке прекращается, если нет
другого действующего пути. Каналы и публикации при этом не удаляются.
Для переноса каналов доверенного владельца новый аккаунт сначала нужно добавить
в список доверенных ID. Перенос, который разорвёт доступ команды, отклоняется
до изменения данных. Открытый режим и прежний режим списка продолжают работать
независимо; новый режим автоматически не включается.

В платном режиме базовые функции доступны бесплатно для канала с менее чем
500 подписчиками. Для функций по подписке, в том числе мультипубликации, нужна
действующая подписка соответствующего канала. При недоступной проверке размера
канала бесплатный доступ по этому условию не предоставляется.

В боте доступны выбор каналов, периода подписки и расчёт стоимости. Для разовой
оплаты можно отдельно подключить YooKassa. Без настройки или при отключённом
провайдере страница остаётся заглушкой: платёж не создаётся и подписка
автоматически не выдаётся. В бесплатном режиме новые платежи не создаются.
Промокоды и начисление реферальных денег не подключены.

Откройте **админка → Подписки и тарифы**. Выберите Telegram или МАКС,
найдите канал по названию, ID или владельцу и откройте его карточку. Подписку
можно выдать или продлить на 30, 90, 180 либо 365 дней или до своей даты.
Действующая подписка продлевается от её будущего окончания, истёкшая — от
текущего времени. Даты показаны в часовом поясе сервиса с UTC-смещением.
Выдача, продление и отзыв требуют проверки показанных изменений и отдельного
подтверждения. Ручное начисление не создаёт платёж.
Подписка принадлежит каналу и сохраняется при переносе данных между аккаунтами.
Перенос или выравнивание сроков действующих подписок в боте требует отдельного
подтверждения показанных изменений.

В блоке **Тарифы** того же раздела задаются цены в целых рублях за один
канал на 30, 90, 180 и 365 дней. Цены общие для Telegram и МАКС. Примените
их общей кнопкой **Сохранить изменения**. Уже созданные заказы сохраняют прежнюю сумму. Для ещё не созданного заказа после смены
тарифов потребуется заново рассчитать стоимость в боте.

При изменении режима оплаты панель обновляет и меню команд Telegram. Если
обновление не подтвердилось для части языков, настройки остаются сохранёнными,
а панель показывает предупреждение. Используйте **Повторить обновление меню
команд** в разделе Telegram. Это не переподключает webhook и не отправляет посты.
Команда `/paysupport` показывает текущее состояние оплаты подписок и контакт
поддержки; автоматический возврат пока не выполняется.

Платное медиа за Telegram Stars внутри публикации — отдельная настройка самого
поста. Она не оплачивает подписку на сервис.

### Необязательная YooKassa

Для подписок Telegram и МАКС используется один магазин YooKassa. Откройте
**админка → Подписки и тарифы → ЮKassa**, укажите **ID магазина (shopId)**
и **Секретный ключ ЮKassa**, включите **Приём платежей** и нажмите
**Сохранить изменения**. Ключ берётся из кабинета вашего магазина ЮKassa.

Сохранённый ключ не показывается в панели. Пустое поле сохраняет действующий
ключ того же магазина. Для смены магазина введите одновременно новый shopId
и новый ключ. Начатые заказы сохраняют прежний магазин и сумму; проверка
таких платежей использует сохранённые прежние реквизиты. Для завершения
их обработки ключ прежнего магазина должен оставаться действующим.
Сохранение настроек не создаёт платёж и не списывает деньги.

Для ручной настройки в защищённом конфиге используется раздел
`telegram_payments`. Выключенный пример без реквизитов:

```php
'telegram_payments' => [
    'version' => 1,
    'enabled' => false,
    'provider' => 'yookassa',
    'shop_id' => '',
    'secret_key' => '',
],
```

`version` — целое число, `enabled` — логическое значение, остальные поля —
строки. Для включения нужны ID магазина и секретный ключ этого магазина;
храните их только в защищённом конфиге, вне репозитория, URL и журналов.
Отсутствующий раздел или `enabled => false` сохраняет заглушку. Политика
бесплатного/платного и открытого/закрытого доступа настраивается независимо.

Адрес и события показаны в блоке **Уведомления ЮKassa**. Перенесите их
в кабинете ЮKassa в **Интеграция → HTTP-уведомления**. Используйте адрес
своего HTTPS-сервиса с селектором `?yookassa_webhook=1`. Например, для установки под
путём `/GitPosted/`: `https://example.org/GitPosted/?yookassa_webhook=1`.
Сохраните фактический префикс из `base_url`. Обработчик принимает только POST
и четыре события: `payment.succeeded`, `payment.canceled`,
`payment.waiting_for_capture`, `refund.succeeded`.

Открытие страницы, GET/HEAD и возврат из YooKassa не создают платёж и не выдают
подписку. Создание требует отдельного подтверждения на странице оплаты;
подписка выдаётся один раз после серверной проверки платежа, магазина, суммы,
валюты и привязки заказа. При неизвестном результате не начинайте новый заказ:
страница сохраняет существующий заказ для проверки. Ожидание capture не выдаёт
подписку; отдельный запрос capture приложение не отправляет.

Автоплатежей, сохранения способа оплаты и автоматических возвратов нет.
Подтверждённый возврат переводит заказ в `refund_review` для разбора поддержкой,
не отменяя автоматически более поздние или вручную выданные подписки.
Автоматические проверки используют перехваченный transport; реальный платёж
и движение денег в этих проверках не выполнялись.

### Подписки и доступ МАКС

Откройте **админка → МАКС → Доступ**. Режимы оплаты и список
разрешённых ID МАКС настраиваются отдельно от Telegram. По умолчанию МАКС
бесплатен и открыт. Связанный Telegram-аккаунт не заменяет ID МАКС в списке.

В платном режиме в настройках МАКС-бота появляется **«Подписка»**. Пользователь
выбирает каналы и срок; оплата оформляется отдельно на каналы МАКС. Подписка
Telegram не открывает функции МАКС, даже если числовые ID совпадают. При
подключённой YooKassa используется тот же обработчик уведомлений
`?yookassa_webhook=1`; заказы и выданные подписки платформ учитываются отдельно.
Повторное уведомление не продлевает подписку второй раз. Администратор может
выдать подписку вручную в разделе **«Подписки и тарифы»**, выбрав платформу МАКС.

## TOP: удержание публикации

График открывается в боте: **Настройки → канал → График размещений**.

В черновике Telegram откройте **«Больше настроек»** и включите **«Топ»**;
в МАКС включите **«Топ»** в настройках поста. Срок по умолчанию — 60 минут;
администратор меняет общую длительность для обоих ботов в разделе Telegram или
МАКС. Срок фиксируется при включении TOP: последующая общая настройка его
не переписывает. Остатки TOP выдаются отдельно пользователю в канале каждой
платформы.

У обычных редакторов и рекламных менеджеров по умолчанию ноль TOP. Владелец
канала задаёт **«Лимит топов»** в правах пользователя или настройках менеджера;
он также доступен в веб-админке. Это общий остаток пользователя в одном канале,
отдельный от закрепов и рекламных категорий. Одна известная публикация TOP
расходует одну единицу; простое включение флага её не списывает. Для владельца
число TOP не ограничено.

Удержание начинается с фактической подтверждённой публикации. Пока оно действует,
GitPosted не публикует в этом канале другие посты, включая посты владельца.
Планирование учитывает будущие TOP и назначения мультипубликаций: дата внутри
чужого удержания и новый TOP, перекрывающий уже запланированный пост, отклоняются
без переноса существующих дат. Точная граница окончания свободна. График показывает
допустимые окна начала TOP выбранной длительности; при неизвестной доставке
свободные окна не обещаются.

В Telegram график показывает события по времени: занятые интервалы TOP,
обычные публикации и свободные варианты полного TOP. Например, TOP
**19:00–20:00** занимает время до 20:00, а следующая публикация допустима
ровно в **20:00**. Можно выбрать месяц, день и час либо указать свою минуту,
после чего выбрать собственный черновик для планирования. Просмотр графика
и выбор времени ничего не бронируют и не списывают: при сохранении дата
проверяется повторно. Для рекламодателя доступен текст свободного времени
без содержимого и ссылок ваших постов.

Неизвестный результат отправки не разрешает повторную отправку или освобождение
удержания по предположению. Отключение флага или удаление уже опубликованного
TOP не сокращает его окно и не возвращает израсходованную единицу. В Telegram
конфликтующий следующий автоповтор сохраняется отдельным неотправленным постом
с ошибкой и прежними параметрами: измените его дату в контент-плане. В МАКС
ожидающий автоповтор сохраняет исходную дату и продолжает ждать освобождения
канала. Ограничение действует на отправки GitPosted; ручные публикации и
другие боты находятся вне его контроля.

## Альбомы и кнопки Telegram

В обычном альбоме из 2–10 фотографий или видео кнопки недоступны: их нет
в редакторе альбома и они не переносятся в отдельное сообщение. Для текста
и одного фото или видео кнопки остаются доступны. Подпись обычного альбома
сохраняется у первой фотографии в пределах лимита Telegram.

Бот собирает фотографии одной отправки перед показом предпросмотра. Пока альбом
загружается, прежнее меню не разрешает опубликовать его неполную версию.

## Веб-режим Telegram

1. В админке откройте **Telegram → Веб-окно настроек поста** и выберите
   **Доступен пользователям**. Сервис должен работать по своему HTTPS-адресу.
2. В боте включите **Настройки → Продвинутые настройки → Веб-режим**.
3. Создайте черновик обычным способом. **«Далее →»** откроет внутри Telegram
   настройки таймера, автоповтора, даты и копирования/пересылки в другие каналы.

Отправка и планирование требуют отдельного подтверждения в окне. При потере
ответа окно проверяет состояние существующей операции. Проверьте результат
в карточке поста, прежде чем начинать новую отправку.

Настройка в BotFather не требуется. При новой установке доступность окна
включена, пользовательский режим изначально выключен. При обновлении прежняя
установка остаётся с обычной кнопкой «Далее» до включения администратором.
Отключение платформы Telegram также отключает веб-режим; настройка МАКС независима.
Через несколько минут открытое окно может потребовать повторного входа из бота.

## Таймер удаления Telegram

Таймер задаётся относительно выхода публикации. Пресет **«≈48 ч»** означает
47 ч 55 мин: пять минут оставлены на выполнение фоновой задачи. Старое значение
«2 дня» показывается тем же безопасным пресетом. Открытие меню само по себе
не меняет сохранённую публикацию.

Сроки больше безопасного предела, например **«3 д · вручную»** или
**«10 д · вручную»**, сохраняют напоминание о ручном удалении. Бот не обещает
автоматически удалить такую публикацию. Это одинаково отображается в черновике,
контент-плане, настройках рекламы и экземплярах серии. Ввод `10д` также означает
ручное удаление. Интервалы автоповтора независимы: повтор «2 д» остаётся ровно
двумя днями.

## Перенос данных между аккаунтами

Начиная с **0.1.0**, можно передать свои данные другому аккаунту той же платформы:
**Telegram → Telegram** или **МАКС → МАКС** внутри одной установки GitPosted.
Это удобно перед сменой или удалением старого аккаунта. Перенос нужно закончить,
пока старый аккаунт доступен.

1. С нового аккаунта запустите того же бота. У нового и старого аккаунтов должен
   быть активный доступ к вашей установке GitPosted.
2. Для **Telegram** получателю не обязательно быть администратором канала
   в самом Telegram. При первой передаче собственного канала старый аккаунт
   должен подтвердить свои права, а бот — сохранить право публикации.
   Ранее полученное через подтверждённый перенос управление можно передать дальше.
   Для **МАКС** оба аккаунта должны оставаться владельцем или администратором
   передаваемого собственного канала на самой платформе.
3. Со старого аккаунта откройте в боте **Настройки → Перенос данных**.
4. Отправьте `@username` или числовой ID нового аккаунта. В МАКС новый аккаунт
   может открыть этот раздел, посмотреть **«Ваш ID МАКС»** и отменить подготовку.
   При неоднозначном или изменившемся username используйте числовой ID.
5. Сверьте показанные имя и ID получателя, количество каналов, публикаций и
   шаблонов. В Telegram в состав входят также папки, выданные права и рекламные
   категории. Нажмите
   **Подтвердить перенос** в течение 15 минут.
6. Убедитесь, что новый аккаунт видит переданные данные. Владение каналами на
   самой платформе и владение ботом передаются отдельно средствами Telegram/МАКС.

Бот меняет владельца существующих записей: посты не создаются заново и не
публикуются в момент переноса. Сохраняются содержимое и вложения, даты, серии,
повторы, режим копии или репоста, закреп и удаление. Личные настройки и часовой
пояс получателя не перезаписываются; сохранённое время публикации не сдвигается.
В Telegram переносятся папки; при совпадении названий используется свободное
название с суффиксом. В МАКС отдельных папок нет.

В собственных каналах прикладным владельцем в GitPosted становится получатель,
права прежнего владельца отзываются. За одну операцию поддерживается до
100 связанных каналов.

**Telegram.** Вместе с публикациями переходят выданные исходному аккаунту права
на чужие каналы, включая каналы без постов, рекламные роли, категории и остатки
квот. Владелец чужого канала не меняется; получатель получает ранее выданные
прикладные права исходного аккаунта. Права администратора на самой платформе
этим действием не выдаются.

Уже существующие публикации и права получателя сохраняются. При совпадении
ролей доступ объединяется без потери выданных разрешений. Совместимые остатки
рекламных квот объединяются; при разных условиях доступа бот сохраняет отдельные
категории с прежними лимитами. Существующие категории сохраняют ID, остатки
и отметки уже списанных квот; совпавшие названия получают свободный суффикс.
Повторное подтверждение не создаёт новые категории и не прибавляет квоты второй раз.

Можно последовательно выполнить **аккаунт 1 → аккаунт 2**, затем
**аккаунт 3 → аккаунт 2**. Второй перенос добавляет данные к уже полученным.
Сначала дождитесь результата первого переноса и только потом готовьте второй.
Два изначально отдельных поста остаются двумя публикациями, даже если их текст
и время совпадают.

Подтверждённая передача собственного Telegram-канала сохраняет управление
в GitPosted за новым владельцем при действующих правах бота. Отключённые или
заблокированные каналы при переносе истории не включаются автоматически.
Одна история отключённого канала не создаёт новую действующую привязку владельца:
после возврата бота может потребоваться обычное подтверждение прав.

**МАКС.** Данные в чужих каналах передаются только при заранее выданных правах.
Рекламные роли, категории и списанные квоты блокируют самостоятельный перенос.
Эти ограничения МАКС не отменяются новыми правилами Telegram.

Для репоста по ссылке из закрытого источника МАКС у получателя должен оставаться
действующий доступ в GitPosted либо сам собственный источник должен входить в
перенос. Некорректный или недоступный источник останавливает перенос;
выбранный репост сам в копию не превращается. Если нужна сохранённая копия,
выберите её явно в настройках поста до подготовки переноса. Поддерживается до
100 уникальных источников таких репостов за один перенос.

Незавершённая отправка, неизвестный результат закрепления, ожидающий комментарий,
удаление или открытый редактор могут временно блокировать операцию. Сначала
завершите действие или подтвердите его результат. Если после предпросмотра
изменились данные или права, откройте перенос заново. Ошибка проверки отменяет
операцию целиком, сохраняя прежних владельцев.

Если подтверждение принято, а ответ бота потерялся, повторите нажатие той же
кнопки: завершённая операция покажет сохранённый результат. Появившиеся позже
данные не передаются повторно. Для нового состава нужен новый перенос.
Функция не создаёт файл экспорта, не переносит данные на другой сервер и
не связывает Telegram-аккаунт с аккаунтом МАКС.

## Уже установленный GitPosted

Команда загрузки и `--resume` предназначены для первоначальной установки и
продолжения её незавершённых шагов. Они не обновляют завершённый GitPosted.
Новые функции появляются в готовой установке после отдельного обновления
приложения; смена версии архива сама по себе не изменяет работающие файлы.

Ручное обновление выполняют с согласованной резервной копией БД, конфигурации,
медиа и bot session. На время замены кода приостанавливают cron и приём событий,
проверяют совместимость схемы и сохраняют пути существующей установки. Нельзя
разворачивать чистую установку поверх рабочей базы или включать две копии
обработчиков с одним состоянием. После замены проверяют runtime и возобновляют
обработку событий. Автоматического обновления готовых установок в этом выпуске нет.

## Продолжение после ошибки

Не запускайте новую установку поверх частично созданной базы. Повторно откройте
мастер в той же браузерной сессии и используйте продолжение сохранённого задания.
Завершённые шаги повторно не запускаются.

При ошибочном или отозванном токене до включения ботов мастер предложит изменить
параметры. Пароль и токены вводятся заново; уже созданная база сохраняется.
Если регистрация webhook уже начиналась, платформа должна остаться включённой:
разрешён новый токен того же бота, его ID повторно проверяется через API.
Webhook secret сохраняется при таком продолжении. Другого бота можно выбрать
или отключить платформу в админке после завершения установки.
После начала включения доступно только продолжение существующего задания.
Если ошибка произошла при подключении домена, исправьте DNS или выбранное имя.
Оба новых проекта могут работать по IP. Путь своего приложения при подключении
домена сохраняется; имя указывается без пути и порта.

Прерванное создание Python-окружения исправляется при продолжении. Если процесс
остановился после закрытия страницы мастера, но до фиксации результата,
перезапуск службы или команда `--resume` восстанавливает доступ к заданию.

Вход по ключу устройства доступен в админке на HTTPS-домене. При работе только
по IP используйте логин и пароль. Неактивные PHP-сессии очищаются после часа;
посты, настройки и сессия Telegram-бота при этом сохраняются.

Если нужна новая личная ссылка или подготовка HTTPS прервалась до открытия мастера:

```bash
sudo bash /opt/gitposted-installer/bootstrap.sh --resume
```

Если первая подготовка не успела разместить этот каталог, повторите исходную
команду загрузки с теми же параметрами и `--resume`. Не сбрасывайте state-файлы и
не удаляйте базу для устранения ошибки. Сообщение о занятом задании означает, что
нужно дождаться его завершения.

Полный пакет сохраняется в `/opt/gitposted-installer` до установки зависимостей.
Поэтому продолжение после ошибки apt не требует уже установленного PHP и
работает после очистки временного каталога загрузчика.

Если второй установщик прервался во время добавления собственной зависимости,
незавершённые состояния dpkg (`iU`, `iF` или ожидающие triggers) требуют проверки
пакетов и явного отдельного обслуживания оператором. При
`SHARED_PACKAGE_CHANGE_REQUIRED` сначала проверьте состояние APT/dpkg и первого
проекта, устраните причину в согласованное время, затем продолжите второй через
`--resume`. Второй установщик не запускает общее исправление всех пакетов через
`dpkg --configure --pending` и не удаляет блокировки. У первоначальной установки
на чистом сервере сохраняется ограниченное восстановление её прерванных пакетов.

В rc.7 обработанная ошибка или таймаут системной команды завершает и её дочерние
процессы. CLI bootstrap обоих проектов обрабатывает `SIGTERM` и `SIGHUP`:
завершает дочерние процессы, освобождает общую блокировку и возвращает безопасный
код `BOOTSTRAP_INTERRUPTED`. Это не отменяет проверку незавершённых пакетов перед
продолжением. Принудительный `SIGKILL`, потеря питания или сбой ядра требуют отдельной
проверки: убедитесь, что прежние дочерние процессы завершились, проверьте APT/dpkg,
nginx, службы первого проекта и сохранённое задание, затем выбирайте продолжение.
Не удаляйте базу или состояние установки для повторного запуска.

После успешного завершения мастер закрыт для новых настроек. Вход администратора
доступен по `https://<адрес>/GitPosted/control/` с созданными вами логином и паролем.

## Где находится установленное приложение

| Назначение | Путь |
| --- | --- |
| Пакет bootstrap и временный broker | `/opt/gitposted-installer` |
| Активный release приложения | `/opt/gitposted/current/src` |
| Releases | `/opt/gitposted/releases` |
| Private config | `/etc/gitposted/config.php` |
| Медиа, runtime и storage | `/var/lib/gitposted` |
| Состояние первоначальной установки | `/var/lib/gitposted-installer` |
| Логи приложения | `/var/log/gitposted` |
| Учётная запись приложения | `gitposted` |
| База и локальный пользователь MySQL | `GitPosted`, `gitposted_app` |

Приложение обслуживается nginx и PHP 8.3 FPM. Apache и Docker не требуются.
Планировщик запускается cron каждую минуту от пользователя приложения. После
успешной установки временный root broker выключается. Сертификаты продлевает
отдельный systemd timer.

Config, данные БД, `.session`, импортированные `.blob`/`.json` и логи относятся
к private состоянию вашей установки. Не добавляйте их в публичный GitHub и не
публикуйте полные ответы диагностических команд с токенами или текстами постов.

## Сборка из исходников

Разработка и сборка не требуют подключать реальных ботов. В корне репозитория:

```bash
python3 -B tests/package_test.py
python3 -B tests/broker_test.py
python3 -B tests/coinstall-test.py
python3 -B tests/coinstall-broker-test.py
php tests/application-test.php
php tests/wizard-test.php
node tests/ui.test.cjs
python3 -B scripts/build.py --output ../INSTALLER-RELEASE
```

Для запуска bootstrap непосредственно из исходников весь пакет и его родительские
каталоги должны принадлежать root и быть закрыты от записи других пользователей.
Обычный пользовательский clone под `sudo` предварительную проверку не пройдёт.
Для установки используйте публичную команду загрузки выше либо отдельный clone,
созданный root в каталоге root, например `/root/GitPosted`. Не меняйте рекурсивно
владельца пользовательского домашнего каталога ради обхода этой проверки.

PHP-проверки требуют PHP 8.3 и расширений приложения; Node.js нужен только для
UI unit tests. Сборщик создаёт `gitposted-installer.tar.gz` и его `.sha256` вне
дерева исходников. Внутри архива — `gitposted-installer/` и `MANIFEST.sha256`.
Секреты, SQLite-сессии, cache/pyc, symlink и лишние файлы сборщик отвергает.

Проверка распакованного release:

```bash
python3 -B scripts/build.py --verify-manifest /absolute/path/to/gitposted-installer
```

Она проверяет и SHA-256, и точный набор файлов. Публичный `install.sh` создаётся
из `scripts/release-loader.sh` с URL конкретного release и его реальной SHA-256
после сборки. Он не входит в собственный архив: это исключает циклическую
зависимость archive hash от загрузчика. Публиковать неподставленные placeholders
или выдуманный hash нельзя.

## Изменения и проверка rc.7

Предварительный выпуск **0.1.0-rc.7** содержит следующие исправления:

- Продление проверяет каждый собственный сертификат независимо. Ошибка старого
  адреса не мешает попытке продлить действующий адрес. Небезопасная конфигурация
  не передаётся Certbot; после остальных попыток возвращается общий безопасный
  код ошибки, поэтому частичный успех не выдаётся за полное продление.
- GitPosted завершает группу дочерних процессов команды при ошибке и таймауте,
  чтобы пакетный или Python-процесс не продолжал менять систему после отказа.
- CLI bootstrap обоих проектов обрабатывает `SIGTERM`/`SIGHUP` с очисткой
  дочерних процессов, освобождением блокировки и кодом `BOOTSTRAP_INTERRUPTED`.
- Оба установщика задают `NEEDRESTART_MODE=l` для Ubuntu 24.04: `needrestart`
  перечисляет службы, требующие перезапуска. Этот режим не отменяет собственные
  post-install скрипты пакетов; изменение общих PHP/nginx/MySQL-зависимостей
  по-прежнему требует отдельного обслуживания.
- После потери ответа на подключение домена мастер проверяет именно текущее
  задание, а не принимает прежнее завершённое задание за результат новой операции.

Финальный прогон: **44/44 Linux suites**, включая 6 групп обоих порядков с
настоящим изолированным nginx. В каждом пакете прошли 8 проверок процессов,
окружения и отмены, а также 7 проверок продления сертификатов. Chrome:
GitPosted **48/48**, GitRePosted **67/67**. Изолированный настоящий мастер
GitPosted с HTTP/PHP/Unix-socket/MySQL — **6/6**, API платформ перехвачены.
Сначала новые регрессии воспроизвели ошибки rc.6; после исправления они прошли.

На уже установленной тестовой паре сохранены hashes конфигурации и состояния,
PID приложений и общих служб. HTTPS обоих проектов, nginx test, схема 33/MAX5

