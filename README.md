# GitPosted — бесплатный аналог Posted для Telegram и МАКС

**GitPosted — бесплатный аналог платного Telegram-бота [Posted (@posted)](https://t.me/posted),
дополненный поддержкой мессенджера МАКС и своими возможностями планирования.**
Это копия идеи удобного постинга, реализованная как самостоятельный проект
с открытым исходным кодом. Используйте для себя, команды или друзей на своём
сервере: лицензионной платы за каждый подключённый канал нет. Код распространяется
по [MIT License](LICENSE); сервер и при необходимости домен оплачивает владелец.
Производительность зависит от ресурсов сервера и ограничений API платформ.

Сайт проекта: [gitposted.ru](https://gitposted.ru/).
Проект независим от Posted; возможности и условия сервисов различаются.
Для автоматической пересылки Telegram ↔ МАКС используйте отдельный
[GitRePosted](https://github.com/SergeyFromMariupol/GitRePosted).

Самостоятельная установка сайта, панели управления и ботов отложенного постинга.
Telegram и МАКС подключаются независимо: можно выбрать любую платформу, обе или
пока оставить только сайт и панель.

## Posted бесплатно: что предлагает GitPosted

Проект создан для тех, кто ищет бесплатную альтернативу Posted, бота для
отложенного постинга или постинг в МАКС со своего сервера. Идея Posted развита
в собственном решении для двух платформ:

- Публикации в Telegram и МАКС через собственных ботов.
- Разовые публикации и долгосрочные серии: период, интервал или отдельные даты.
- Дубликаты поста со своим временем, закрепом и таймером удаления.
- Импорт публикаций по ссылке, выбор копии или репоста с учётом доступа к источнику.
- Перенос публикаций, собственных каналов и шаблонов на другой аккаунт той же
  платформы через **Настройки → Перенос данных**; в Telegram переносятся и папки.
- Открытый код MIT, своя панель управления и установка на свой сервер.
- Без лицензионной платы за каждый канал: расходы на сервер оплачивает владелец.

Для автоматической пересылки между каналами и платформами предназначен
[GitRePosted](https://github.com/SergeyFromMariupol/GitRePosted); GitPosted
отвечает за подготовку и планирование публикаций.

GitPosted is a free, self-hosted, open-source alternative to the paid Posted
Telegram bot (@posted), with Telegram and MAX support, scheduled posts,
recurring publications, independent post duplicates and account data transfer
within the same platform.

## Выпуск 0.1.1

Telegram-канал можно подключить по `@username`, ссылке `https://t.me/username`,
числовому ID или пересланному сообщению. Проверяются именно канал, права бота
и права подключающего человека. Успешное подключение подтверждается личным
сообщением с эффектом 🎉, если клиент Telegram поддерживает его отображение.

Перенос Telegram теперь включает выданные права на чужие каналы, рекламные
роли, категории и остатки квот. Получателю не обязательно быть администратором
канала в самом Telegram: внутри GitPosted сохраняется подтверждённая передача
управления, а бот должен сохранять необходимые права. Уже имеющиеся данные
получателя сохраняются; несколько исходных аккаунтов можно перенести в один
последовательно. Отключённые каналы не включаются автоматически. Правила переноса
МАКС остаются прежними.

Таймер удаления Telegram показывает безопасный автоматический предел как
**«≈48 ч»** — фактически 47 ч 55 мин. Более длинные сроки явно отмечены
**«вручную»**: бот напомнит об удалении. Интервалы повторов не менялись.

Порядок подключения, переноса и выбора таймера описан в
[инструкции](docs/USAGE.md#подключение-telegram-канала).
Повторный запуск установщика не обновляет уже завершённую установку.

## Предыдущий выпуск 0.1.0

Добавлен перенос данных **Telegram → Telegram** и **МАКС → МАКС** в одной
установке GitPosted. Получатель указывается по `@username` или числовому ID;
перед подтверждением бот проверяет аккаунт и права в каналах. Существующие
публикации сохраняют даты, повторы, режим репоста, закреп и удаление. Повторное
нажатие завершённого подтверждения показывает прежний результат.

Дополнительно исправлены проверки прав и закрытых источников МАКС, обработка
неизвестного результата закрепления и конфликты одновременных действий с
каналами. Проверки переноса по сети выполняются до блокировки очереди публикаций.

Подготовить перенос нужно до удаления старого аккаунта. Порядок действий и
ограничения описаны в [инструкции](docs/USAGE.md#перенос-данных-между-аккаунтами).
Повторный запуск установщика не обновляет уже завершённую установку.

## Предыдущий выпуск rc.8

Новые установки поддерживают общий IP, общий домен и разные домены с
постоянными путями `/GitPosted/` и `/GitRePosted/`. У приложений отдельные
мастера и админки; порядок установки не меняет их адреса. Старый корневой

Проверки и ограничения приёмки — в [инструкции](docs/USAGE.md#проверки-выпуска-rc8).

## Предыдущий выпуск rc.7

Предварительный выпуск **0.1.0-rc.7** исправляет продолжение после сбоев совместной установки:
ошибка продления старого адреса больше не отменяет попытки продлить остальные
собственные сертификаты, а мастер отличает текущее задание подключения домена
от прежнего завершённого задания при потере ответа. Оба установщика завершают
дочерние процессы команд при ошибке или таймауте. Оба bootstrap обрабатывают
`SIGTERM`/`SIGHUP` с очисткой дочерних процессов и кодом `BOOTSTRAP_INTERRUPTED`.
При установке пакетов в обоих
проектах `needrestart` работает в режиме списка и сам не перезапускает службы;
собственные действия пакетных скриптов проверяются отдельно.

Пройдены 44/44 Linux suites, Chrome GitPosted 48/48 и GitRePosted 67/67,
6/6 изолированных HTTP/PHP/Unix/MySQL сценариев GitPosted. Новая чистая пара
rc.7 на VPS отдельно не устанавливалась; результаты rc.6 ниже исторические.
Условия продолжения, ручное обслуживание прерванного
APT/dpkg и границы восстановления — в
[инструкции](docs/USAGE.md#изменения-и-проверка-rc7).

## Установка

Нужен **Ubuntu Server 24.04 LTS**: чистый сервер либо сервер с завершённой
установкой GitRePosted, которую установщик смог проверить. Нужны доступ по SSH
с `sudo`, публичный IPv4 и
открытые входящие TCP 80/443. Рекомендуется 2 ГиБ RAM, нужно от 4 ГиБ свободного
диска. Установщик сам готовит nginx, PHP 8.3 FPM, MySQL,
HTTPS и фоновые задачи. Существующие сайты и базы автоматически не перезаписывает.

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash
```

Для установки сразу на домене сначала направьте его DNS на сервер:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash -s -- --host example.org
```

При первой установке без `--host` используется публичный IP сервера. Если IP нельзя определить
однозначно, добавьте `--public-ip YOUR_PUBLIC_IPV4`.

После подготовки сервер покажет **личную одноразовую HTTPS-ссылку**. Откройте её:
вход в `/GitPosted/install/` произойдёт автоматически. Вручную вводить код не нужно.
Ссылку сохраняйте только у себя: она даёт доступ к первоначальной настройке.

В браузере задайте логин и пароль администратора, выберите нужных ботов и
проверьте их токены. hCaptcha и Telegram API для импорта ссылок — дополнительные
настройки. Обычный запуск не требует номера телефона или личной Telegram-сессии.
Мастер проверит конфигурацию, зарегистрирует выбранные webhooks и откроет ссылку
на `/GitPosted/control/`. Тестовые публикации при установке не отправляются.

Если подготовка прервалась или нужна новая личная ссылка:

```bash
sudo bash /opt/gitposted-installer/bootstrap.sh --resume
```

Уже запущенное задание мастер не начинает заново: его состояние сохраняется.
После успешной установки первоначальный мастер закрывается; управление остаётся
в панели администратора.

## GitPosted и GitRePosted на одном сервере

Начиная с **0.1.0-rc.8**, новые установки обоих проектов используют постоянные
пути `/GitPosted/` и `/GitRePosted/`. Можно начать с любого проекта: полностью
завершите его браузерный мастер, затем установите второй.

| Размещение | GitPosted | GitRePosted |
|---|---|---|
| Общий IP без домена | `https://IP/GitPosted/control/` | `https://IP/GitRePosted/control/` |
| Общий домен | `https://example.org/GitPosted/control/` | `https://example.org/GitRePosted/control/` |
| Разные домены | `https://posted.example.org/GitPosted/control/` | `https://reposted.example.org/GitRePosted/control/` |

`IP` и домены в таблице замените своими. Без `--host` первая установка выбирает
публичный IP. Вторая без `--host` использует текущий проверенный адрес первого
проекта. Для разных доменов передайте каждому свой `--host`; для общего домена
укажите одинаковое имя либо не передавайте его второй установке. Все выбранные
имена должны иметь A-запись на IPv4 сервера. Установщик не меняет DNS.

Команды для общего IP или наследования адреса:

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitPosted/main/install.sh | sudo bash
```

```bash
curl -fsSL https://raw.githubusercontent.com/SergeyFromMariupol/GitRePosted/main/install.sh | sudo bash
```

Для домена добавьте к нужной команде `-s -- --host example.org` после `sudo bash`.
Для разных доменов укажите разные имена. Для предварительной проверки добавьте
`--dry-run`: она проверяет совместимость, но не заменяет установку зависимостей.

Главная `/` показывает ссылки на размещённые на этом адресе приложения.
У каждого проекта свой мастер (`/GitPosted/install/` или `/GitRePosted/install/`),
логин, пароль и админка. Персональная ссылка одного проекта не открывает другой.
Токены ботов должны быть разными; в каналы можно добавить обоих ботов с нужными
правами. Telegram и МАКС можно пропустить и подключить позже.

nginx, MySQL и PHP общие; базы `GitPosted`/`GitRePosted`, системные пользователи,
данные, конфигурации, cookies и службы приложений разделены. Один HTTPS-сертификат
общего адреса обслуживается установщиком, который первым занял этот адрес;
второй использует его. Продление выполняется автоматически. Приложения слушают
только внутренние порты, снаружи доступны через общий nginx.

Установщик проверяет соседний проект и использует общую блокировку. При
`SHARED_INSTALL_BUSY` дождитесь другого системного шага. При прерывании
продолжайте именно свой проект через `--resume`, а браузерное задание — в его
мастере. Не удаляйте state-файлы, блокировки и базы для обхода проверки.
Сторонние сайты или произвольная существующая MySQL этим режимом не подхватываются.

**Старые установки rc.7 и ниже:** корневые адреса `/control/` сохраняются.
Повторный загрузчик не обновляет и не переносит готовое приложение. Рядом с
проверенной старой установкой второй проект требует отдельный явный домен и
тоже использует прежний корневой режим. Общий адрес с постоянными путями
предназначен для двух новых установок rc.8 и новее; автоматической миграции
готовых установок в этом выпуске нет.

Подробнее: [установка и продолжение](docs/USAGE.md), [инструкции для работы с кодом](AGENTS.md).

`install.sh` загружает конкретный release с закреплённой SHA-256. Внутренний
manifest проверяет файлы пакета. Production config, данные БД, медиа и сессии в
этот репозиторий не входят.
